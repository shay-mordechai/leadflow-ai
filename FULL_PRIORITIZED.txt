# PHASE 1: CRITICAL SECURITY (The "Unknown Unknowns")
# ==============================================================================
1.  [Security] Webhook Idempotency: Implement a Redis/DB layer to prevent processing the same payment/message webhook twice (Replay Attacks).
2.  [Security] Rate Limiting (API): Integrate `fastapi-limiter` to restrict requests per IP/User (e.g., 60 req/min) to prevent DDoS.
3.  [Security] Rate Limiting (Auth): Strict limits on /login and /verify-otp (e.g., 5 attempts/hour) to stop Brute Force.
4.  [Security] Webhook Signature Verification: Validate `X-Twilio-Signature` and Stripe headers to ensure requests are actually from providers.
5.  [Security] SQL Injection Hardening: Audit all `text()` queries in SQLAlchemy and enforce parameter binding.
6.  [Security] PII Redaction in Logs: Middleware that automatically masks emails, passwords, and phone numbers before writing to logs.
7.  [Security] CSP (Content Security Policy): Hardened headers for Next.js to prevent XSS attacks.
8.  [Security] HSTS Enforce: Force HTTPS strictly via headers (Strict-Transport-Security) in FastAPI middleware.
9.  [Security] Audit Logging: Create an `audit_logs` table tracking WHO changed WHAT (User ID, Action, Timestamp, IP).
10. [Security] Session Invalidations: Ability to revoke all tokens for a user (e.g., "Log out all devices").
11. [Security] Dependency Scanning: Add `bandit` or `safety` check to CI/CD to find vulnerable Python packages.
12. [Security] Docker/Podman Hardening: Run containers as non-root user (User 1001) strictly.
13. [Security] CORS Strictness: Replace `allow_origins=["*"]` with specific domain list from Environment Variables.
14. [Security] API Key Rotation: Logic to allow rotating internal secrets without downtime.

# ==============================================================================
15. [Reliability] Graceful Shutdown: Handle `SIGTERM` to allow finishing active AI requests before killing the container.
16. [Reliability] Database Connection Pooling: Tune SQLAlchemy pool size and overflow for high concurrency.
17. [Reliability] Circuit Breakers: If OpenAI/Gemini is down, fail fast instead of hanging the request.
18. [Reliability] Exponential Backoff: Retry logic for failed Twilio messages (1s, 2s, 4s, 8s...).
19. [Reliability] Dead Letter Queue (DLQ): Save failed Webhooks to a DB table for manual replay later.
20. [Reliability] Health Check (Deep): Check DB and Redis connectivity in `/health` endpoint, not just return 200.
